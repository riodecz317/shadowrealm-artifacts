ShadowRealm Agents is a fleet of specialist Claude Code subagents that turns one prompt into a structured brief, a built change on its own branch, and a pull request — passing through privacy, compliance, quality, and governance review along the way. No agent pushes to main. No agent skips a gate.

How it runs

How a request becomes a merged PR

Every lane — design, finance, docs, analysis — follows the same sequence after the brief is written. Each gate returns one of a small set of verdicts; a BLOCK stops everything and escalates straight to a human rather than waiting to be found in a report.

01

prompt-creator-agent writes the brief

Converts the raw request into a structured brief at .claude/briefs/ and picks a lane — design, graphics, mobile, exec-insights, process, data-pipeline, analysis, architecture, docs, finance, accounts-payable, or treasury.

01.5

architect-agent decides structure — only if needed

Runs only when the brief introduces a new component, integration, or tech-stack decision. Writes an ADR that becomes required reading for the builder. Skipped for most briefs.

02

The lane's builder implements the change

Commits to a feature branch and stops — never pushes, never opens the PR. Which agent runs here depends entirely on the lane the brief picked.

03

data-privacy-agent checks exposure

Scans the diff and any referenced data files for personal or sensitive data, secrets, and hosting exposure — the first gate, before anything else is spent reviewing the work.

SAFE CAUTION BLOCK
04

compliance-agent checks obligations

Legal, regulatory, contractual, and licensing review, consuming step 03's findings rather than re-deriving them. Never issues a legal conclusion — flags for human/DPO review.

COMPLIANT NEEDS REVIEW BLOCK
05

quality-agent checks the work itself

Lane-agnostic content and code quality gate — the only reviewer narrative-only output (exec, PM reports) gets.

PASS REVISE BLOCK
06

dashboard-scrutiny-agent — design lane only

UI/UX/accessibility critique against the original brief. REVISE sends the change back to step 02, up to two rounds, before it's treated as stuck.

PASS REVISE BLOCK
07

ai-governance-agent audits the process

Checks AI-content disclosure, whether irreversible actions had a human checkpoint, and provenance for the round. ESCALATE stops everything; FLAGGED is noted but doesn't block.

ATTESTED FLAGGED ESCALATE
08–09

Pull request, then a human merges

A PR opens only once every gate above has passed. The user proofreads on GitHub and merges — the pipeline never merges its own work.

Why nothing pushes to main directly: earlier versions of these agents ran git add . && git commit && git push origin main autonomously — no branch, no build check, no review gate, and a real risk of two agents clobbering the same file. Every agent now stops at "committed to a feature branch," and a PR opens only once every gate above returns a passing verdict.

Two agents run outside this sequence entirely: admin-control-agent audits whether the sequence above was actually followed for every open branch, and risk-assessment-agent rolls findings from the gates into a standing, likelihood × impact Risk Register — both on their own cadence, not per-change.

Newest lane

The finance lane

Added to cover FP&A, payables, and treasury monitoring for the organization — plus a structurally separate agent for the individual user's own finances. Built with a planned future bank/ERP connection in mind, without building that connection yet.

FP&A
finance-agent
Reads actuals against budget and prior forecast, rolls the forecast forward, and drafts variance commentary a budget owner can act on. Hands complex, multi-driver forecasting to data-scientist-agent rather than modeling it itself.
Accounts Payable
ap-agent
Two/three-way matches invoices to POs and receipts, proposes GL coding, drafts chase reminders for stalled approvals. Never marks an invoice approved, coded-final, or paid — segregation of duties, by design.
Treasury
treasury-agent
Tracks cash position against forecast, flags margin deterioration and spend anomalies, maintains a financial-control/covenant status log. States an as-of date on every figure — never implies a feed is live when it isn't.
Personal
personal-finance-agent
Budgeting, personal risk review, bill and subscription tracking — for the individual, not the org. Writes only to a gitignored folder; never opens a branch, never a PR.
→

One shared contract, not three. The no-live-access disclaimer, the extract schema, and the landing-zone path are defined once in finance-lane-conventions.md — all three enterprise agents point to it instead of independently restating it.

→

Raw data never enters the reviewed surface. Source extracts live in workspace/finance/inbox/, gitignored. Only the derived report — the forecast, the match table, the treasury readout — gets committed and reviewed.

→

Personal and enterprise stay structurally separate. Not a shared setting, a shared connector, or a shared folder — two disjoint paths, one of which never touches git at all.

ADR · 2026-08-30

No agent here has live bank or ERP API access today — each operates on manually-supplied extracts, deliberately, until a sandbox account exists to test a real connection safely. When that connection is built, it's scoped as a data-engineer-agent brief — one connector feeding all three finance agents — not a new dedicated agent, and not capability grafted onto the three directly. Full reasoning in ADR-2026-08-30-finance-agent-fleet-review.md.

What holds it together

Guardrails

The rules that keep twenty-two independently-invoked agents from stepping on each other.

One verdict vocabulary, reused everywhere

Every gate returns a passing / cautionary / blocking verdict from a small, consistent set — never a vague "looks fine" or a silent pass.

PASS-CLASS REVIEW-CLASS BLOCK-CLASS

A BLOCK escalates immediately

Never left sitting in a report for someone to find later — data-privacy-agent, compliance-agent, and ai-governance-agent all surface a hard stop directly to the user the moment it's found.

Segregation of duties

ap-agent proposes matches and coding; it never posts, approves, or pays. Matching and paying should never be the same actor, human or agent.

Human checkpoints on irreversible actions

ai-governance-agent checks that anything hard to undo — including ingesting a real, non-synthetic data source for the first time — had a traceable human sign-off.
